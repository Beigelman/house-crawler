## Ranked findings

1. **Major runtime defect — stale profile matches (C31).** `src/property/runner.ts:161` saves new observed attributes, then `src/property/runner.ts:165` saves only the matching subset. `supabase/migrations/20261117235107_property_interface.sql:160` only inserts matches; neither path removes a previous match when a fresh observation fails the profile. With production `propertyStore(admin)` and deterministic providers, collect a matching 100 m² listing under a profile requiring at least 90 m², then observe the same identity at 80 m². The local result was `{"case":"no-longer-matching","matches":1,"currentArea":"80"}`. The stored match now refers to a listing that fails a required observed attribute. Update membership for observed candidates and prove both matching and no-longer-matching observations through runner → production store → local database. AC31 currently stops at the pure predicate.
2. **Major runtime defect — a later matching profile loses the new-listing email (C63).** `src/property/runner.ts:161` persists all candidates before deciding whether they match the current profile. `src/property/runner.ts:166` adds only that save's fresh rows to the notification set. When the first profile returns a three-bedroom listing but requires four bedrooms, that listing becomes stored without entering `news`. A later three-bedroom profile returns the same listing and matches it, but its `fresh` result is empty. With two enabled profiles ordered by UUID and the production store, the local result was `{"case":"later-profile-matches-new-listing","emails":0,"listings":1,"matches":1}`. Preserve new identities across the whole run and intersect with matches across all profiles before sending. Prove this sequence through the production store and the existing email adapter boundary.
3. **Major proof gaps — authorization and secrets (C3, C4).** AC03 makes only SELECT requests to tables, most empty, plus enqueue calls (`tests/database_test.ts:47`, `tests/database_test.ts:59`). It does not attempt non-owner mutations. Reach populated table reads, direct unauthorized writes and worker RPC execution, and scan a build made with harmless server-secret sentinels. SQL review found owner/grant restrictions, but those restrictions are not established by the frozen proof as a complete claim.
4. **Major proof gaps — collection, lease, diagnostics and email boundaries (C31, C39, C41, C44, C46–C50, C54–C55, C63–C64).** Most worker proofs use the in-memory store in `tests/worker_test.ts:42`.
