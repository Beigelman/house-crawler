## Ranked findings

1. **Runtime validation defect — C28 overlength name accepted.** `supabase/migrations/20261117235107_property_interface.sql:47` constrains `char_length(trim(name)) between 1 and 80` but stores the untrimmed text. A leading space plus 80 `x` characters has actual length 81 and is accepted. Independent local reproduction returned `{"inputLength":81,"acceptedRows":1,"storedLength":81}`. The previous name was restored immediately. Thus a profile name outside the frozen 1–80-character bound is stored instead of rejecting the entire write. `tests/database_test.ts:136` checks 81 plain x characters; the supplementary AC28 test at `tests/database_test.ts:616` adds invalid parameter families but does not add padded names. Require the stored name length to be at most 80 (while retaining blank-name rejection) and prove padded overlength writes reject atomically. Make the migration update an existing table's constraint as well as a fresh schema; editing only the CREATE TABLE definition would leave already-migrated databases permissive.

The reproducer was an `rtk deno eval` importing local-only `tests/local.ts`, selecting the existing name, executing `update property_profile set name=${" "+"x".repeat(80)} where id=${profile} returning name`, reporting input/returned lengths, then restoring the selected name and closing the local connection. It ran between proof targets, never concurrently with their fixture truncation. It changes input data at unmodified HEAD and is not an injected code fault.
